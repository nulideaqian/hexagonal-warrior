> **量尺定义（严口径）**：虚构参数 = 输出中出现、但输入未提供的**可验证事实性参数**（容量 / 功率 / 接口 / 材质 / 价格 / 时长 / 芯片型号等），每处计 1。"大容量""高性价比"等无数字的模糊夸词不计入严口径，另记"模糊夸词"。"可验证" = 读者拿输出对照实物或商品页，真伪立判。

# 结论

## T2.1 输入质量对比（已关账）

1. **信息缺口不会消失，会被编造填上**：裸词"充电宝" → 严口径虚构 8 处（智能芯片、多重保护、高品质电芯……），模型自动补全了一个"市面上最常见的充电宝"。顺带触发"聊天解释模式"（开头"好的，作为营销专家……"）——输入越贫瘠，模型越想跟你商量。
2. **给足参数 = 给模型上镣铐**：完整 JSON → 虚构 8→1；再加"只使用给定参数"防线 → 0。
3. **参数防线 ≠ 表达防线，两条独立的线**：组③参数归零，但"相比同类产品更具价值"仍在——比较性宣传是表达层违规，参数约束拦不住，要单独设防。

## T2.2 few-shot（3/4 格，最后一格待补跑）

1. **示例教的是"写法+分寸"整包**：标题格式跟示例走（自创编号消失）、学会算账动作（"年均成本极低"）、学会非竞品锚点对比（"相比频繁更换电池"）；粘贴降级（丢加粗）仍学到八九成——示例是稳定资产，应住进代码常量。
2. **信息匮乏时，few-shot 把虚构升级成"更像真的"假数字**：裸词+示例 → 标题编出"10000mAh"。比"大容量"式模糊吹更危险——看起来可信，标错容量是退赔级事故。
3. **（待补）** 最后一格 = 完整 JSON + 禁虚构防线 + 示例，三件套齐上，跑完补最终结论。
